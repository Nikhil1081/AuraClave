# NexMeet

A modern, dark-themed video meeting starter built with React, TypeScript, LiveKit, Supabase and an optional Groq-powered meeting-notes assistant.

## Included

- Responsive landing page and dashboard
- Supabase email/password sign-up and sign-in
- Protected dashboard and meeting routes
- LiveKit room access tokens generated by a serverless API
- LiveKit `VideoConference` UI (camera, microphone, screen sharing and in-room chat)
- Optional authenticated Groq meeting-notes endpoint
- Vercel deployment configuration

## Requirements

- Node.js 20 or newer
- A Supabase project
- A LiveKit Cloud project
- A Vercel account for deployment
- Optional Groq API key for AI meeting notes

## 1. Install

```bash
npm install
```

Copy `.env.example` to `.env.local` and fill in the values.

### Frontend variables

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY
```

### Server-only variables

```env
LIVEKIT_URL=wss://YOUR_PROJECT.livekit.cloud
LIVEKIT_API_KEY=YOUR_LIVEKIT_API_KEY
LIVEKIT_API_SECRET=YOUR_LIVEKIT_API_SECRET
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_ANON_KEY=YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY
GROQ_API_KEY=YOUR_GROQ_API_KEY
GROQ_MODEL=llama-3.3-70b-versatile
```

`SUPABASE_ANON_KEY` is used server-side to validate Supabase access tokens. The Supabase publishable/legacy anon key is safe to expose under Supabase's intended RLS model; never use a service-role key in the browser.

**Never add `VITE_` to LiveKit or Groq secrets. Never commit `.env.local`.**

## 2. Configure Supabase Auth

In Supabase Dashboard → Authentication → URL Configuration:
- Set Site URL to your local/deployed app URL.
- Add `http://localhost:3000/**` to Redirect URLs for local development if needed.
- For deployment, add your Vercel domain to Redirect URLs.

For a quick test, email confirmation may be enabled or disabled in Supabase Authentication settings. If enabled, confirm the signup email before signing in.

## 3. Run locally

This project includes Vercel serverless functions in `/api`, so run it using Vercel's local development server:

```bash
npx vercel dev
```

The first run may ask you to log in to Vercel and link a project. The local app usually runs at `http://localhost:3000`.

Do not use only `npm run dev:vite` to test meetings: Vite's dev server does not execute the `/api` serverless functions.

## 4. Test a meeting

1. Create a NexMeet account and sign in.
2. Select **Create meeting**.
3. Allow camera and microphone permissions.
4. Copy the browser URL and send it to another person.
5. The other person must sign in to your NexMeet deployment and open the meeting link.
6. Use the LiveKit toolbar for microphone, camera, screen share and chat.

The current starter requires every participant to have a NexMeet account. It does not yet implement guest links, host/moderator roles, meeting scheduling, persistent meeting history, or recording.

## 5. Deploy to Vercel

1. Push this folder to a GitHub repository.
2. Import the repository into Vercel.
3. Add all environment variables from the sections above in Vercel → Project Settings → Environment Variables.
4. Set the build command to `npm run build` and output directory to `dist` (Vercel generally detects Vite automatically).
5. Deploy.
6. Add your deployed URL to Supabase Authentication → URL Configuration.

## 6. Optional Groq meeting notes endpoint

The authenticated endpoint is `POST /api/ai`.

Headers:
```http
Authorization: Bearer YOUR_SUPABASE_ACCESS_TOKEN
Content-Type: application/json
```

Body:
```json
{
  "task": "summarize",
  "text": "Paste meeting transcript or notes here..."
}
```

For action items, set `"task": "action-items"`.

This endpoint summarizes text supplied by the user. It does **not** automatically record or transcribe live meeting audio. Add an explicit consent-based transcription workflow before processing participants' voices.

## Security and production notes

- Rotate any API secret that has been pasted into a chat, screenshot, issue, or repository.
- Keep LiveKit and Groq secrets server-side only.
- Configure Supabase Row Level Security before adding database tables.
- The current token endpoint checks authentication and validates room-name syntax. Before public production, add meeting membership/invitation checks, abuse prevention/rate limits, and authorization rules for room roles.
- LiveKit and Supabase free plans have usage limits and may change. Check current provider pricing and quotas before public launch.
- Use HTTPS in production. Camera and microphone access generally require HTTPS (localhost is also allowed).
